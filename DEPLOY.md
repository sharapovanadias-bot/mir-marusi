# Деплой «Мира Маруси» через GitHub

Сайт — чистая статика (HTML + CSS + JS), без сборки и бэкенда. Все пути относительные,
поэтому он заработает на любом хостинге без правок.

Git-репозиторий уже создан локально: 110 файлов, 1 коммит, ветка `main`.

---

## ⚠️ Сначала главное: какие площадки подходят «Миру Маруси»

Здесь есть развилка, которую легко пропустить. «Мир Маруси» — **коммерческий бренд-сайт**
(товары, цены, в перспективе продажи), и лицензии бесплатных тарифов относятся к этому
по-разному:

| Площадка | Коммерция на free | Трафик | Вердикт |
|---|---|---|---|
| **Cloudflare Pages** | ✅ разрешена | безлимит | **рекомендую** |
| **Netlify** | ✅ разрешена | 100 ГБ/мес | хорошая альтернатива |
| GitHub Pages | ❌ запрещена | 100 ГБ/мес (soft) | только для черновика |
| Vercel Hobby | ❌ запрещена | 100 ГБ/мес | нужен Pro $20/мес |

**GitHub Pages** прямо запрещает использовать себя как бесплатный хостинг для онлайн-бизнеса,
интернет-магазина и сайтов, нацеленных на коммерческие транзакции; допускаются лишь
кнопки донатов и краудфандинга. **Vercel Hobby** ограничен личным некоммерческим
использованием, причём трактует «коммерческое» широко — вплоть до сайта, который просто
рекламирует товар. **Cloudflare Pages и Netlify** коммерцию на бесплатном тарифе разрешают.

Поэтому: **репозиторий держим на GitHub, а публикуем через Cloudflare Pages** — код
хранится в Git, деплой автоматический по каждому `push`, но без нарушения лицензии.

## Шаг 1. Залить код на GitHub (общий для всех вариантов)

Репозиторий уже готов. Осталось создать пустой репо на GitHub и запушить.
**Токен/пароль нужен ваш** — у меня доступа к вашему аккаунту нет.

1. Создать пустой репозиторий: **https://github.com/new**
   (без README, без .gitignore — они уже есть в проекте)
2. Выполнить, подставив свой логин и имя репозитория:

```bash
cd /home/user/mir-marusi
git remote add origin https://github.com/ВАШ_ЛОГИН/mir-marusi.git
git push -u origin main
```

GitHub спросит логин и пароль — **вместо пароля нужен Personal Access Token**
(Settings → Developer settings → Personal access tokens → Fine-grained → доступ `Contents: write`).
Обычный пароль GitHub давно не принимает.

Репозиторий можно делать **приватным** — Cloudflare Pages и Netlify работают
с приватными репо на бесплатном тарифе.

## Шаг 2. Публикация

### Вариант A. Cloudflare Pages — рекомендуемый

1. **https://dash.cloudflare.com** → Workers & Pages → Create → Pages →
   **Connect to Git**
2. Выбрать репозиторий `mir-marusi`
3. Настройки сборки — **оставить пустыми**:
   - Framework preset: **None**
   - Build command: *пусто*
   - Build output directory: `/`
4. Save and Deploy

Через минуту сайт на `mir-marusi.pages.dev`. Дальше каждый `git push` в `main`
деплоится автоматически, а ветки получают свои превью-ссылки.

Свой домен: Custom domains → Set up a domain. HTTPS бесплатно и автоматически.

Лимиты free: безлимитный трафик, 500 сборок в месяц, до 20 000 файлов и 25 МБ на файл —
у нас 110 файлов, крупнейший 228 КБ, запас огромный.

### Вариант B. Netlify

1. **https://app.netlify.com** → Add new site → Import an existing project → GitHub
2. Выбрать репозиторий
3. Build command — пусто, Publish directory — `.`
4. Deploy

В проекте уже лежит `netlify.toml` с кэшированием шрифтов и картинок на год.

### Вариант C. GitHub Pages — только как черновик

Годится, пока сайт — демонстрация макета без продаж. Как только появятся реальная
продажа и оплата, надо будет переехать (лучше сразу начать с Cloudflare).

Settings → Pages → Source: **Deploy from a branch** → `main` / `(root)` → Save.
Через минуту: `ВАШ_ЛОГИН.github.io/mir-marusi/`.

Файл `.nojekyll` уже добавлен — без него GitHub игнорировал бы служебные папки.
Важно: репозиторий должен быть **публичным** (Pages из приватных репо требует платный план).

## Шаг 3. После публикации

### Заменить домен-заглушку

В `index.html` в двух местах — `<link rel="canonical">` и JSON-LD бренда — стоит
`https://mirmarusi.example/`. Пока он там, поисковики считают канонической
несуществующую страницу.

```bash
cd /home/user/mir-marusi
sed -i 's|https://mirmarusi.example|https://ВАШ-ДОМЕН|g' index.html
git commit -am "Настоящий домен" && git push
```

Остальные 14 страниц пока без `canonical` — на работу это не влияет, но перед
индексацией и рекламой их стоит проставить.

### Проверить

- [ ] Заголовки рукописные (Caveat), текст — Neucha
- [ ] Цена отображается как «690 ₽» — знак рубля на месте
- [ ] Лента каракулей на главной едет
- [ ] Корзина считает: 1 книга = 1 040 ₽ с доставкой

## Ограничения прототипа

Корзина живёт в `localStorage` браузера, платёжный шлюз не подключён, формы никуда
не отправляются. Для реальных продаж понадобится бэкенд или готовое решение
(кнопки оплаты ЮKassa / Tinkoff либо платформа вроде Ecwid).
