# ШАГ 4. Подключить Cloudflare Pages

1. Зарегистрироваться / войти: **https://dash.cloudflare.com**
2. В меню слева — **Workers & Pages**
3. **Create application** → вкладка **Pages** → **Connect to Git**
4. Авторизовать GitHub: **Install & Authorize**.
   Можно дать доступ только к репозиторию `mir-marusi`, не ко всем сразу
5. Выбрать репозиторий `mir-marusi` → **Begin setup**

# ШАГ 5. Настройки сборки — САМОЕ ВАЖНОЕ

Сайт статический, собирать нечего. Поля должны быть такими:

| Поле | Значение |
|---|---|
| Project name | `mir-marusi` (станет адресом `mir-marusi.pages.dev`) |
| Production branch | `main` |
| Framework preset | **None** |
| Build command | **оставить пустым** |
| Build output directory | `/` |
| Root directory | оставить пустым |

⚠️ Если указать сюда любую build-команду, деплой упадёт — сборщика в проекте нет.
Пустое поле здесь правильно, документация Cloudflare прямо говорит: «If you do not
need a build step, leave the Build command field blank».

Нажать **Save and Deploy**. Через 1–2 минуты сайт будет на `mir-marusi.pages.dev`.

# ШАГ 7. Свой домен (когда будет)

1. В проекте Pages → вкладка **Custom domains** → **Set up a domain**
2. Ввести домен и следовать подсказкам (если домен уже в Cloudflare —
   DNS-запись создастся сама; если нет — покажут, какие NS прописать у регистратора)
3. HTTPS-сертификат выпустится автоматически, бесплатно

## Сразу после подключения домена — заменить заглушку

Заглушка `https://mirmarusi.example` встречается в трёх файлах:
`index.html` (`<link rel="canonical">` и JSON-LD бренда), `robots.txt` и `sitemap.xml`.
Пока она там, поисковики считают канонической несуществующую страницу.

```bash
cd /home/user/mir-marusi
sed -i 's|https://mirmarusi.example|https://ВАШ-ДОМЕН|g' index.html robots.txt sitemap.xml
git commit -am "Настоящий домен" && git push
```

После этого добавьте карту сайта в Яндекс.Вебмастер и Google Search Console:
`https://ВАШ-ДОМЕН/sitemap.xml`

Остальные 14 страниц пока без `canonical` — на работу сайта не влияет,
но перед индексацией и рекламой стоит проставить.

# Дальнейшая работа

После настройки любой `git push` в `main` автоматически публикует изменения:

```bash
cd /home/user/mir-marusi
git add -A
git commit -m "что изменил"
git push
```

Ветки, отличные от `main`, получают отдельные превью-ссылки — удобно показывать
правки, не трогая живой сайт.

## Лимиты бесплатного тарифа Cloudflare Pages

- Трафик и запросы — **безлимит** (для статики)
- 500 сборок в месяц, 1 параллельная
- 20 000 файлов, 25 МБ на файл
- Коммерческое использование **разрешено** — в отличие от GitHub Pages и Vercel Hobby

## Ограничения прототипа

Корзина живёт в `localStorage` браузера, платёжный шлюз не подключён, формы никуда
не отправляются. Для реальных продаж понадобится бэкенд или готовое решение
(кнопки оплаты ЮKassa / Tinkoff либо платформа вроде Ecwid).
