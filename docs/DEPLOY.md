# Публикация «Мира Маруси»: GitHub + Cloudflare Pages

Пошаговая инструкция. Всё, что можно было сделать за вас, уже сделано:
Git-репозиторий готов, конфиги кэширования на месте, лимиты проверены.

От вас нужны только действия в браузере и один `git push` — доступа к вашим
аккаунтам у меня нет.

# ШАГ 1. Создать репозиторий на GitHub

1. Открыть **https://github.com/new**
2. **Repository name**: `mir-marusi`
3. Видимость: **Private** или Public — Cloudflare Pages работает с обоими
   на бесплатном тарифе
4. ⚠️ **НЕ ставить галочки** «Add a README», «Add .gitignore», «Choose a license» —
   репозиторий должен быть пустым, иначе push упрётся в конфликт
5. **Create repository**

# ШАГ 2. Получить токен доступа

Пароль GitHub при пуше не принимает — нужен токен.

1. Открыть **https://github.com/settings/personal-access-tokens/new**
   (Settings → Developer settings → Personal access tokens → Fine-grained)
2. **Token name**: `mir-marusi-deploy`
3. **Expiration**: на ваше усмотрение (90 дней — разумно)
4. **Repository access** → *Only select repositories* → выбрать `mir-marusi`
5. **Permissions** → Repository permissions → **Contents: Read and write**
6. **Generate token** и **скопировать** — показывается ровно один раз

# ШАГ 3. Отправить код на GitHub

Подставьте свой логин и выполните. Команда спросит логин, затем пароль —
**вместо пароля вставьте токен из шага 2**:

```bash
cd /home/user/mir-marusi
git remote add origin https://github.com/ВАШ_ЛОГИН/mir-marusi.git
git push -u origin main
```

Если хотите обойтись без ввода — можно вшить токен прямо в адрес
(учтите: он останется в конфиге репозитория):

```bash
git remote add origin https://ВАШ_ЛОГИН:ТОКЕН@github.com/ВАШ_ЛОГИН/mir-marusi.git
git push -u origin main
```

Проверка: обновите страницу репозитория — там должны появиться 15 HTML-файлов и папка `assets`.

# ШАГ 4. Подключить Cloudflare Pages

1. Зарегистрироваться / войти: **https://dash.cloudflare.com**
2. В меню слева — **Workers & Pages**
3. **Create application** → вкладка **Pages** → **Connect to Git**
4. Авторизовать GitHub: **Install & Authorize**.
   Можно дать доступ только к репозиторию `mir-marusi`, не ко всем сразу
5. Выбрать репозиторий `mir-marusi` → **Begin setup**

# ШАГ 5. Настройки сборки — САМОЕ ВАЖНОЕ

Сайт статический, собирать нечего. Поля должны быть такими:

| Поле | Значение |
|---|---|
| Project name | `mir-marusi` (станет адресом `mir-marusi.pages.dev`) |
| Production branch | `main` |
| Framework preset | **None** |
| Build command | **оставить пустым** |
| Build output directory | `/` |
| Root directory | оставить пустым |

⚠️ Если указать сюда любую build-команду, деплой упадёт — сборщика в проекте нет.
Пустое поле здесь правильно, документация Cloudflare прямо говорит: «If you do not
need a build step, leave the Build command field blank».

Нажать **Save and Deploy**. Через 1–2 минуты сайт будет на `mir-marusi.pages.dev`.

# ШАГ 6. Проверить результат

Откройте выданную ссылку и убедитесь:

- [ ] Заголовки рукописные (Caveat), основной текст — Neucha
- [ ] Цена показывается как «690 ₽» — знак рубля на месте
- [ ] Лента каракулей на главной едет
- [ ] Работает переход в раздел «Книги» и открывается карточка товара
- [ ] Корзина считает: 1 книга = 1 040 ₽ с доставкой
- [ ] На телефоне вёрстка не разъезжается

# ШАГ 7. Свой домен (когда будет)

1. В проекте Pages → вкладка **Custom domains** → **Set up a domain**
2. Ввести домен и следовать подсказкам (если домен уже в Cloudflare —
   DNS-запись создастся сама; если нет — покажут, какие NS прописать у регистратора)
3. HTTPS-сертификат выпустится автоматически, бесплатно

## Сразу после подключения домена — заменить заглушку

В `index.html` в двух местах (`<link rel="canonical">` и JSON-LD бренда) стоит
`https://mirmarusi.example/`. Пока она там, поисковики считают канонической
несуществующую страницу.

```bash
cd /home/user/mir-marusi
sed -i 's|https://mirmarusi.example|https://ВАШ-ДОМЕН|g' index.html
git commit -am "Настоящий домен" && git push
```

Остальные 14 страниц пока без `canonical` — на работу сайта не влияет,
но перед индексацией и рекламой стоит проставить.

# Дальнейшая работа

После настройки любой `git push` в `main` автоматически публикует изменения:

```bash
cd /home/user/mir-marusi
git add -A
git commit -m "что изменил"
git push
```

Ветки, отличные от `main`, получают отдельные превью-ссылки — удобно показывать
правки, не трогая живой сайт.

## Лимиты бесплатного тарифа Cloudflare Pages

- Трафик и запросы — **безлимит** (для статики)
- 500 сборок в месяц, 1 параллельная
- 20 000 файлов, 25 МБ на файл
- Коммерческое использование **разрешено** — в отличие от GitHub Pages и Vercel Hobby

## Ограничения прототипа

Корзина живёт в `localStorage` браузера, платёжный шлюз не подключён, формы никуда
не отправляются. Для реальных продаж понадобится бэкенд или готовое решение
(кнопки оплаты ЮKassa / Tinkoff либо платформа вроде Ecwid).
