# Что такое токен и зачем он нужен

**Коротко:** GitHub с 2021 года не принимает обычный пароль от аккаунта, когда код
загружают через командную строку. Вместо пароля нужен **токен** — длинная строка
вида `github_pat_11ABC...`. Это как одноразовый пароль, который вы выдаёте
конкретной программе и только для конкретного репозитория.

Токен нужен **только если код загружается командой**. Если загружать файлы
через сайт GitHub мышкой — токен не нужен вообще (см. Способ 1 ниже).

---

# СПОСОБ 1. Без токена, всё мышкой в браузере (проще)

Подходит, если командная строка вам непривычна.

### 1.1. Скачать архив сайта

В рабочей папке лежит файл **`mir-marusi-site.zip`** (8.6 МБ) — скачайте его к себе
на компьютер и распакуйте. Получится папка с файлами `index.html`, `books.html`
и папкой `assets`.

### 1.2. Создать репозиторий

1. Открыть **https://github.com/new**
2. **Repository name**: `mir-marusi`
3. Выбрать **Private** (приватный) или **Public** — оба работают с Cloudflare
4. Галочки «Add a README file», «Add .gitignore», «Choose a license» — **не ставить**
5. Кнопка **Create repository**

### 1.3. Загрузить файлы мышкой

На странице пустого репозитория будет ссылка **«uploading an existing file»**
(в тексте «…or push an existing repository» ищите строчку выше).
Прямая ссылка: `https://github.com/ВАШ_ЛОГИН/mir-marusi/upload/main`

1. Открыть проводник с распакованной папкой
2. Выделить **всё содержимое папки** (Ctrl+A) — именно содержимое,
   а не саму папку целиком
3. Перетащить в окно браузера
4. Внизу нажать зелёную кнопку **Commit changes**

⚠️ Через браузер GitHub принимает максимум 100 файлов за раз, а у нас 114.
Поэтому в два захода:

- **Заход 1:** выделить все файлы в корне папки (15 штук `.html`, плюс `robots.txt`,
  `sitemap.xml`, `_headers`, `netlify.toml` и папку `docs`) → перетащить →
  **Commit changes**. Это 24 файла.
- **Заход 2:** снова открыть `.../upload/main`, перетащить **папку `assets`**
  целиком → **Commit changes**. Это 90 файлов, укладывается в лимит.

Папки при перетаскивании сохраняют структуру — `assets/img/story/...` останется
как есть, ничего не перемешается.

Готово, код на GitHub. Переходите к Cloudflare (ШАГ 4 в основной инструкции).

# СПОСОБ 2. С токеном, через командную строку

Если хотите правильный git-процесс с историей изменений.

### 2.1. Открыть страницу создания токена

**https://github.com/settings/personal-access-tokens/new**

Путь мышкой, если ссылка не открылась: аватар в правом верхнем углу →
**Settings** → в самом низу левого меню **Developer settings** →
**Personal access tokens** → **Fine-grained tokens** → кнопка **Generate new token**.

### 2.2. Заполнить поля — по порядку сверху вниз

Экран выглядит как длинная форма. Вот что вписывать в каждое поле:

| Поле на экране | Что делать |
|---|---|
| **Token name** | Написать `mir-marusi-deploy` (любое имя, для себя) |
| **Description** | Можно пропустить |
| **Resource owner** | Оставить свой аккаунт (он выбран по умолчанию) |
| **Expiration** | Выбрать `90 days` — через 90 дней токен сам умрёт, это нормально |
| **Repository access** | Выбрать кружок **Only select repositories** |
| ↳ появится поле **Select repositories** | Нажать, начать печатать `mir-marusi`, выбрать его в списке |
| **Permissions → Repository permissions** | Это длинный список прав. Нужно найти в нём строку **Contents** |
| ↳ строка **Contents** | Справа от неё выпадающий список, там написано `No access`. Открыть его и выбрать **Read and write** |

**Про «Contents: Read and write»** — это и есть та строчка, которая была непонятна.
Расшифровка: `Contents` = «содержимое репозитория, то есть сами файлы»,
`Read and write` = «читать и записывать». То есть вы разрешаете токену
изменять файлы в репозитории. Без этого права загрузка кода не пройдёт.

Список прав длинный (Actions, Administration, Codespaces, **Contents**, Deployments…),
он отсортирован по алфавиту — `Contents` примерно четвёртый сверху.

Строка **Metadata** переключится в `Read-only` сама — так и должно быть, не трогайте.

Больше **ничего в списке менять не нужно**.

### 2.3. Создать и скопировать

Внизу страницы — кнопка **Generate token**. Затем GitHub покажет токен
**один-единственный раз**. Скопируйте его сразу и сохраните куда-нибудь
(заметки, менеджер паролей). Если потеряете — просто создадите новый.

### 2.4. Загрузить код

```bash
cd /home/user/mir-marusi
git remote add origin https://github.com/ВАШ_ЛОГИН/mir-marusi.git
git push -u origin main
```

Спросит `Username` — ваш логин на GitHub.
Спросит `Password` — **вставить токен**, не пароль от аккаунта.

⚠️ При вставке токена в терминал **на экране ничего не появится** — ни точек,
ни звёздочек. Это не зависание, так задумано ради безопасности. Вставили — Enter.
